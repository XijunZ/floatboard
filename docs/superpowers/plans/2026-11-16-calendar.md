# Calendar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Calendar tab (day + week) that mirrors every Google calendar of every connected account, keeps tasks and
their Google events in step, links meetings and tasks by short visible ids, and shows the next meeting on the bar and
today's meetings on the phone.

**Architecture:** Google is the truth for events; the Mac keeps a rebuildable cache in `board.sqlite`
(`cal_calendars`, `cal_events`) filled by incremental sync. Writes to Google go through a durable calendar outbox.
Task ↔ event logic and all storage live in `FloatBoardCore` (offline, no network, tested); the Google API client lives
in `FloatBoardConnectors`; views live in the `FloatBoard` app target. A general `links` table holds id links
(task ↔ event now; jots, people, decisions later).

**Tech Stack:** Swift 6 tools / Swift 5 mode, SwiftUI + AppKit, raw SQLite (`DB`), Google Calendar API v3 over
`URLSession`, engine in TypeScript (Cloudflare Worker, vitest), phone app plain JS.

**Spec:** `docs/superpowers/specs/2026-11-16-calendar-design.md` (approved 16 Nov 2026). Read it first; decision
numbers (D1–D14, C1–C7) below refer to it.

## Global Constraints

- `board.sqlite` stays the truth for tasks; `FloatBoardCore` makes no network calls (`scripts/check-core-offline.sh`).
- Schema: bump `DB.schemaVersion` to the next free number **at build time** (10 today; another session may have
  taken 11) and add one `upgrade(from:)` step; update `DB.schema` and `Tests/Fixtures/schema-v<N>.json` so new and
  upgraded boards match (`schemaChecks`).
- Every `try?` carries a `try?-ok:` justification (`scripts/check-silent.sh`); every error goes to Activity.
- No personal details in code, docs, fixtures or commit messages (public repo; pre-commit hook enforces).
- No AI attribution in commits. Commit after each task; don't push until the user has seen the result.
- Checks run only on scratch paths: `FLOATBOARD_DB`, `FLOATBOARD_CREDS`, `FLOATBOARD_BACKUPS` (see README).
- New Google scope: `https://www.googleapis.com/auth/calendar.calendarlist.readonly`, added to
  `GoogleAuthConfig.scopes` after `calendar.events`.
- Default time zone `Europe/London` (D12). Sync window: 30 days back, 90 days ahead. Sync every 60 s while the
  Calendar tab or the bar's meeting is visible, every 5 min otherwise while awake, once on wake. Watchdog warns when a
  shown calendar hasn't synced for 30 min while online. Bar shows the next meeting from 60 min before it starts.
- Ids: tasks `T-<card id>`, events `E-<short_id>` (D13). FloatBoard-made events carry
  `extendedProperties.private.floatboard_card = "<card id>"` (C6).

## Review Focus

1. **Travel / time zone change** with the Mac on Asia/Shanghai: date-only tasks must stay date-only and on the same
   day; timed tasks keep their instant. → Task 1 check `due_date_only_survives_zone_change`.
2. **Offline edits then quit**: a moved event made offline must still reach Google after relaunch.
   → Task 6 check `calendar_outbox_survives_reopen`.
3. **Account missing the new scope** (connected before this release): calendars can't be listed; the user must see
   "Reconnect to show your calendars", nothing crashes, existing "Add to calendar" still works.
   → Task 5 check `calendar_list_403_marks_needs_reconnect`.
4. **Event deleted in Google for a task with notes and links**: task, notes and other links stay; only time and
   event link go. → Task 7 check `google_delete_keeps_task_drops_time`.
5. **Same edit both sides** (title changed on the board and in Google before a sync): newer wins per field, the
   other field untouched. → Task 7 check `per_field_newer_wins`.
